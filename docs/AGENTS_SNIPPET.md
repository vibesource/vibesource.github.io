# Optional AGENTS.md section: VibeSource workshop

Copy the section below into a project's `AGENTS.md` **only when the owner has opted into workshop tracking**. Tailor paths to the project. It is intentionally short; read the central guide for detailed rules.

```md
## VibeSource workshop journal (opt-in)

This project may be documented on VibeSource, an independent public engineering workshop: https://github.com/vibesource/vibesource.github.io.

Before preparing site content, read the canonical guide:
https://github.com/vibesource/vibesource.github.io/blob/master/docs/WORKSHOP_GUIDE.md

Keep implementation evidence, decisions and progress in this repository. When a meaningful milestone, failure, architecture decision, pause or abandonment occurs, suggest a concise entry for `docs/workshop/STATUS.md`. Do not produce trivial per-commit summaries or spend development time on unnecessary publishing work.

A proposed public summary is **not approved for publication**. Private source, internal infrastructure, logs, recordings, family information and machine-specific details must remain private. Credit upstream authors and distinguish experimental from validated capabilities.

Prepare a public-safe draft locally first. Ask for explicit approval before creating any branch, issue, PR or asset in the public VibeSource repository. Never merge, publish, change repository visibility or automatically sync project commits without explicit permission. The project's current task and acceptance criteria take priority.
```

### Example project-start instruction

> Read `AGENTS.md` and the project requirements. If VibeSource workshop tracking is enabled, create or update the private `docs/workshop/STATUS.md` with the project's question and initial status. Keep it short. Do not publish anything to the website. During development, suggest journal updates only for meaningful decisions or milestones, and ask before preparing a public site PR.
